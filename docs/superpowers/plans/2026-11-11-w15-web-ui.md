# W15 Web UI: Task-Level Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Implementers work under the epic's implementer brief; this plan does not restate it.

**Goal:** Give each web UI rule one owner. One modal hook decides Escape, Tab, scroll lock and focus restore for every modal surface. Each list that loads in several requests keeps its paging rules in one Core reducer with load ids, and a single-request view uses `useStaleGuard`. One notices list replaces the outline's three notice slots, and one component renders every dismissible notice. One hook serves both stored on/off preferences, one array holds the static routes, and `styles.css` gets section markers, a z-index scale, one compact button and a test that walks real rules.

**Source:** `docs/superpowers/plans/2026-11-09-maintainability-review-fixes.md` § W15, its Global Constraints and § W19; bean `pkm-nbl3`. Branch `refactor/web-ui`, read at `main` @ `9e54b7dc`, with W4, W7, W8, W12, W13 and W17 merged.

**Architecture:** Behaviour pins and red tests first, then the change, per task. New Core modules (`focusWrap.ts`, `filesPaging.ts`, `backlinksPaging.ts`, `unlinkedStatus.ts`, `outline/notices.ts`) carry the rules, each with an event-table test in the shape of `journalPaging.test.ts`. The shells keep fetches, timers and the DOM. Tasks are grouped into lanes that touch disjoint files. The stylesheet lane runs in its own worktree with its own `node_modules` and merges last; the docs task runs after everything.

**Tech stack:** React 18 hooks, vitest + jsdom, Playwright (Chromium), `postcss` (new dev dependency, test-only), typescript-eslint.

## Review Focus

Inputs no single task's tests are certain to exercise, most likely to bite first. Each names its pin.

1. Two modals open at once. Capture-phase listeners on one target all run, whatever `stopPropagation` says, and they run in registration order, outer first. Without a stack, one Escape closes both and the outer one restores focus under the inner. Task 1 `with two modals open only the later one answers Escape, Tab and onKey`.
2. A double click before React re-renders. `Files`' `loadMoreInFlight`, `BacklinksSection`'s `refreshInFlight` and `UnlinkedSection`'s `inFlight` are refs read synchronously. A plain `useReducer` state read in a handler is the last render's, so two clicks would start two loads or two links. Tasks 6 to 8 drive their reducers through `useReducerRef` (Task 5), whose `current()` sees a dispatch before the re-render; each has a two-clicks test.
3. A notice setter that returns a new object when nothing changed. Today `setEditNotice(null)` on an already-null slot bails out. A slots object rebuilt on every applied command would commit every mounted outline once more per keystroke. Task 10 `withNotice returns the same slots when the slot already holds that value`; `perf/check.sh frontend` scenarios F and J.
4. Focus restore after a confirm opened from the outline. The large-delete confirm opens from a block selection; restoring focus must not land in a textarea the outline no longer treats as focused. Task 2's real-keypress check, item 6.
5. Stored preference strings. A build that reads `pkm:sidebar` or `pkm:block-stamps` with different values silently resets every user's choice. Task 12 `the stored strings are the ones earlier builds wrote`.
6. `ruleFor`'s matching changes under `postcss`. The regex helper matched any rule whose selector text ended with the argument; the walker matches selector-list members. An assertion can start passing against a different rule. Task 14's old-versus-new comparison.

### Task 1: `useModal` and `focusWrap`

**Implementer:** opus (the focus trap, Escape order and focus restore).

**Files:** create `web/src/focusWrap.ts`, `web/src/focusWrap.test.ts`, `web/src/useModal.ts`, `web/src/useModal.test.tsx`. **Interfaces:**
- `focusWrap.ts` (`// pattern: Functional Core`): `focusWrapTarget<T>(focusables, active, shiftKey): T | null`, moved verbatim with its doc comment. `FOCUSABLE_SELECTOR = 'a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'`. It widens `PdfViewer`'s list by the form controls, as that list's comment asked of anyone adding them.
- `useModal.ts` (`// pattern: Imperative Shell`):
  ```ts
  export interface ModalOptions {
    surfaceRef: RefObject<HTMLElement | null>;
    initialFocusRef: RefObject<HTMLElement | null>;
    onClose: () => void;
    /** Focus returns here on unmount; without it, to the element focused
     * when the modal mounted. Either only while still in the document. */
    triggerRef?: RefObject<HTMLElement | null>;
    /** "cycle" wraps Tab through the surface; "pin" holds it on the
     * initial target. */
    trap?: "cycle" | "pin";
    /** Keys other than Escape and Tab, heard only while this modal is the
     * topmost. */
    onKey?: (event: KeyboardEvent) => void;
  }
  export function useModal(options: ModalOptions): void
  ```
- A module-level stack of open modals. On mount: push; read the restore target (`triggerRef.current`, else `document.activeElement` unless it is `document.body`); when the stack goes from empty to one, save `document.body.style.overflow` and set `"hidden"`; focus `initialFocusRef.current`. One `window` keydown listener per modal, capture phase, that acts only when its modal is the stack's top. Escape: `preventDefault`, `stopPropagation`, `onClose()`. Tab, `"cycle"`: `focusWrapTarget` over `surfaceRef.current.querySelectorAll(FOCUSABLE_SELECTOR)`; when it names a target, `preventDefault` and focus it. Tab, `"pin"`: `preventDefault` and focus the initial target. Any other key: `onKey?.(event)`. On unmount: remove the listener; note whether this modal was the top, then pop; when the stack empties, restore the saved overflow; when it was the top and the restore target `isConnected`, focus it.
- `onClose` and `onKey` are read through refs updated every render; the effect's dependency list is empty, so a parent's re-render never re-runs it.
- The header comment states the two rules nothing else enforces: capture-phase listeners on `window` all run whatever `stopPropagation` says, so only the topmost acts; and Escape is stopped in the capture phase because hosts (the assistant panel's `onKeyDown`) also close on Escape and a portal's events bubble through the React tree.

## Traps

- **Capture listeners on one target.** `stopPropagation` in a `window` capture listener stops the event reaching `document` and the React root, but every other `window` capture listener still runs, in registration order (outer modal first). Only the stack makes the inner modal the one that answers. *Detect:* Task 1's two-modal tests.
- **Restore from a modal that is not on top.** An outer modal unmounting under an inner one must neither unlock scrolling nor move focus. *Detect:* `closing the outer modal first neither unlocks scrolling nor moves focus`.
- **Effect re-runs.** A `useModal` effect that depends on `onClose` re-focuses the initial target on every parent render (the bug `GoodlinksLink` and `PdfViewer` work around today). *Detect:* `a new onClose identity on re-render neither re-runs the effect nor moves focus`.
- **jsdom has no native Tab.** jsdom moves no focus on a Tab keydown, so unit tests cover only the wrap and pin decisions; the "browser's own order already stays inside" path (`focusWrapTarget` returns null) is seen only in Chromium. *Detect:* `modal-keys.spec.ts` and the real-keypress list.
- **Refusing on stale state.** A reducer read through `useState` inside a click handler is the last render's. *Detect:* each of Tasks 6 to 8's two-clicks test, which fail under a plain `useReducer`.
- **New objects for unchanged state.** A reducer case or notice setter that rebuilds an unchanged state commits a render. `useReducerRef` and `useState` skip a render only when the same object comes back. *Detect:* `withNotice returns the same slots…`, `a reducer that returns the same state causes no render`, perf scenarios F, I and J.
- **The Files generation bump.** It happens at the keystroke (`filterChanged`), not when the debounced reload fires; a reducer that bumps only on `reloadStarted` lets Select all run on the old filter's list during the debounce. *Detect:* `Select all clicked in the filter debounce window selects nothing`.
- **`ConfirmCard`'s key.** Without a key per `confirm()` call, a second confirm reuses the mounted card and focus stays where it was. *Detect:* `a second confirm() refocuses the confirm button`.
- **`PdfPages` needs `Document`.** The inline overlay must render inside `<Document>`; moving it outside renders nothing, with no error in jsdom. *Detect:* `pdf.spec.ts`' overlay canvas assertion.
- **Stored strings.** `useStoredToggle` writes the fallback on mount, as `useStoredPref` does; swapping the `[off, on]` pair would read every saved "collapsed" as off and then overwrite it. *Detect:* `the stored strings are the ones earlier builds wrote`; real check item 8.
- **`.btn-compact` source order.** Placed before `.btn-secondary`, it loses on padding and the notices grow. *Detect:* `the compact button is one class` plus the Chromium look in real check item 7.
- **`pnpm install` in a symlinked worktree** rewrites the main checkout's `node_modules` under every session. Only the orchestrator installs, only after `rm` of the link. *Detect:* `test -L web/node_modules` before any install.
- **`verify-deps-before-run`.** After the `package.json` change, a pnpm script in a worktree whose `node_modules` predates it refuses to run. Implementers pass `--config.verify-deps-before-run=false`.
- **Shared e2e state.** `modal-keys.spec.ts` writes only to its own page (`ownPage`) and cancels the delete. It still gets a full-suite run before merge.

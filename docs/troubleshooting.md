# Troubleshooting

Failures this system has produced, keyed by what you would observe. The docs
under [architecture/](architecture/overview.md) describe the system as it is;
incident history lives only here.

| Column | Holds |
|---|---|
| Symptom | What someone saw, with the literal banner, error string or route |
| Cause | The mechanism, and the guard by identifier where `Where` does not make it obvious |
| Where | The architecture section that owns the mechanism and states the rule |
| Ref | The bean with the investigation, the test that pins the behaviour, or an em dash |

Add one row per failure that happened, or that a review reproduced, under the
area whose doc owns the mechanism. The fix story belongs in the bean and the
rule in the `Where` section.
